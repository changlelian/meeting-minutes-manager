# 本地运行与连接配置设计说明

## 目的

让用户启动当前会议纪要 Demo 后，可自行填写 LLM 服务 Host 与 API Key；密钥不进入源码、浏览器持久化存储、会议历史、导出文件或 URL。

## 已选方案

1. 在静态 HTML 中保存或直连 Key：实现简单，但浏览器会暴露密钥，不采用。
2. 增加同机本地服务：页面仅向 127.0.0.1 提交配置，服务在内存中保管 Key，状态接口永不回传 Key，采用。
3. Electron 主进程与操作系统凭据库：正式桌面版的长期方案；本次保持无依赖的 Node 本地服务。

用户已要求直接执行，因此按方案 2 实现并启动本地服务。

## 行为

- 本地服务仅绑定 127.0.0.1，提供页面、POST /api/config 与 GET /api/status；请求 Host 必须与当前 127.0.0.1 端口匹配，配置 POST 的 Origin 也必须匹配。
- 设置弹窗提供 Base URL、API Key（密码字段）与 Qwen 模型。
- 页面把配置发给同源本地服务，成功后立即清空 API Key 输入框。
- 服务只在进程内保存 Key；状态接口仅返回配置状态、Host 与模型，绝不回传 Key。
- 页面响应使用禁止 iframe 嵌入的安全响应头，配置端点仅接受 application/json。
- Host 必须是没有用户名或密码的 HTTP(S) URL。
- 当前 Demo 不会向用户填写的 Host 发起 LLM 或 ASR 请求；真实 Paraformer/SenseVoice 与 Qwen 调用留给后续受保护的服务端实现。
- 停止本地服务或刷新其进程后，用户需要重新填写 API Key。

## 非目标

- 不将 Key 写入 localStorage、文件、历史纪要、日志或导出文件。
- 不实现云同步、账号、桌面凭据库或真正的百炼音频/模型调用。
