# 历史纪要 Markdown 导出设计

## 意图

用户已经可以在本地历史中搜索和查看已保存的会议，但当前“导出 Markdown”只作用于编辑中的当前草稿。为让历史浏览形成可分享闭环，允许从历史详情直接下载当前显示的那条已保存记录。

## 已考虑的方式

- **导出当前显示的历史详情（采用）：** 复用既有 Markdown 格式和浏览器下载流程；筛选后自动展示的匹配记录也可被准确导出。它不修改当前草稿、历史记录或隐私边界。
- **把历史记录恢复到当前编辑器后再导出：** 会意外覆盖用户未保存草稿，与现有“查看历史不改变当前草稿”的约定冲突。
- **删除或清空历史：** 有隐私价值，但属于破坏性记录管理，需要确认、写入失败处理与更多交互设计，不作为本轮范围。

## 目标与交互

- 在历史详情的保存时间后提供一个有明确名称的“导出此纪要”按钮。
- 点击后下载 UTF-8 Markdown，内容从当前显示的历史记录的主题、逐字稿和已保存纪要直接生成，包含原始逐字稿。
- 筛选导致当前保存选择不匹配时，导出筛选后详情临时显示的第一条匹配记录；无匹配或无历史时禁用按钮。
- 成功与下载受阻时保留页面现有反馈区，并在打开的历史弹窗内显示一个礼貌状态提示，明确区分历史导出与当前会议导出。

## 边界与约束

- 不新增接口、不调用 Qwen/Paraformer、不读取或写入 API Key。
- 不写入 `localStorage`、不更改 `meeting-demo.history.v1`、不改变活动会议的主题、逐字稿或纪要。
- 继续复用 `toMarkdown()`、安全文件名规则、原生下载方式及现有焦点样式；不更改当前会议导出在“千问纪要过期”时的保护逻辑。
- 不提供历史恢复编辑、删除、云同步或批量导出。

## 验收

- 筛选后的历史详情可下载对应的 UTF-8 `.md`，其中含该历史主题、概览及原始逐字稿，且不含未保存的当前草稿。
- 导出时无网络请求，历史 localStorage 字节内容和当前草稿保持不变。
- 无匹配时导出按钮禁用，完整测试套件继续通过。
