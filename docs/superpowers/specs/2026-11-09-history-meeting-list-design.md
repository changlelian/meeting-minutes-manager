# 历史会议纪要列表设计说明

## 目的

让用户在离线 Demo 中保存已生成的会议纪要，并从历史列表只读查看对应的完整逐字稿与结构化纪要，而不覆盖正在编辑的当前会议。

## 已选方案

考虑了预置静态列表、浏览器本地存储和服务端数据库三种方式。选择浏览器 `localStorage`：它符合当前单文件、离线、无账号的 Demo 边界，刷新页面后仍能查看本机历史，也不向任何服务上传会议数据。

## 行为

- 页面首次使用时提供少量明确标注的演示历史记录，便于立即查看效果。
- 用户点击“生成纪要”时，若当前逐字稿非空，将会议主题、原始逐字稿、结构化纪要和保存时间写入历史；同一场当前会议再次生成时更新同一条记录而不重复新增。
- “重置”更名为“新建会议”，只清空当前草稿并开始一场新会议，历史记录保留。
- 顶栏“历史纪要”显示记录数；点击后打开原生只读弹窗。左侧是可键盘选择的会议列表，右侧展示该条的主题、保存时间、完整逐字稿与会议纪要。
- 历史查看不会改写当前主题、逐字稿、计时器或当前纪要；录音进行时，历史入口不可操作。
- 存储读取、解析或写入失败时，功能退化为当前页面会话内列表，并给出简洁说明。

## 数据边界

使用版本化键 `meeting-demo.history.v1`。每条记录为 `{ id, topic, savedAt, transcript, minutes }`，按最新保存时间倒序显示，最多保留 20 条。`transcript` 保存用户原始换行，页面所有历史内容均通过 `textContent` 渲染。

## 不做的事

- 不提供云端同步、账号、多设备共享、删除/编辑历史或真正的数据库。
- 不改变百炼/千问的安全边界：本功能不上传数据，也不在浏览器保存 API Key。
