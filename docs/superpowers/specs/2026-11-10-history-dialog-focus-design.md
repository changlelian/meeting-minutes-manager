# 历史会议弹窗键盘焦点设计

## 意图

“历史会议纪要”已经支持搜索、查看逐字稿和导出，但键盘用户打开弹窗时焦点会落到关闭按钮而不是高频的搜索框；在筛选框有内容时，浏览器首个 Escape 还会清空搜索而不是关闭弹窗。本轮让该对话框具备可预测、可逆的键盘焦点流程。

## 目标

- 点击“历史纪要”后，原生对话框打开且焦点进入 `#history-filter`。
- 当筛选框有内容且用户未处于输入法组合状态时，首个 Escape 关闭对话框而不清空筛选词。
- 通过关闭按钮、Escape 或直接调用 `dialog.close()` 关闭历史对话框后，焦点回到 `#history-button`。
- 关闭和重新打开期间保留筛选词、已选历史记录、当前会议主题与逐字稿。

## 非目标

- 不修改历史数据、本地存储、搜索算法、录音、草稿或百炼/Qwen 集成。
- 不改变输入法组合期间 Escape 的浏览器行为。
- 不增加全局快捷键，也不改变其他对话框的 Escape 规则。

## 方案比较

1. 只给搜索框加 `autofocus`：能改善初始焦点，但不能处理筛选框的 Escape 清空行为或保证焦点归还；不采用。
2. 打开后显式聚焦、监听 `close` 归还焦点，并仅在已输入筛选词且非组合状态时截获 Escape：覆盖真实键盘路径，范围最小；采用。
3. 在整个对话框全局拦截 Escape：会改变关闭按钮或其他控件的原生交互，且可能打断输入法；不采用。

## 验收

- 从当前会议主题输入框打开历史时，活动元素变为 `#history-filter`。
- 输入一个能匹配内置记录的筛选词后，一次 Escape 关闭对话框、焦点回到历史按钮，筛选词和当前会议输入值保持不变。
- 再次打开后，筛选词及对应的历史选择仍可见，搜索框再次获得焦点。
