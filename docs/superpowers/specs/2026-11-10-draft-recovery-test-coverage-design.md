# 本地草稿恢复测试覆盖设计

## 意图

上轮独立审阅确认本地草稿恢复实现可用，但留下两项非阻塞测试缺口：删除失败提示的无障碍语义没有被浏览器回归固定，已被其他标签页删除的草稿也没有在一次后续持久化机会后被明确证明不会重新出现。本轮只补足这些可观察契约。

## 目标

- 在真实浏览器的删除失败路径中，验证错误文案位于 `#draft-restore-dialog` 内，且状态元素使用 `role="status"`、`aria-live="polite"`、`aria-atomic="true"`。
- 在草稿已缺失的恢复弹窗路径中，触发一次无输入的 `pagehide` 持久化机会，并验证 `meeting-demo.draft.v1` 仍为 `null`。
- 保留现有“重试删除成功”和“缺失草稿关闭提示”的用户可见行为。

## 非目标

- 不修改 `index.html`、本地存储模型、恢复文案、录音、历史会议或百炼/Qwen 集成。
- 不尝试用浏览器自动化替代真实屏幕阅读器或视觉对比度评估。
- 不在测试中派发输入事件，因为那会合法创建一份新的草稿，无法证明缺失快照未被复写。

## 方案比较

1. 通过搜索 HTML 源码验证 ARIA 属性：只能证明文本存在，不能验证运行时弹窗内的元素关系；不采用。
2. 在现有 CDP 浏览器流程中读取弹窗子元素与属性，并在相同页面触发 `pagehide`：验证真实运行时 DOM 和同步持久化边界；采用。
3. 增加屏幕阅读器自动化或视觉快照：价值更高但需要额外环境、断言策略和跨浏览器维护，超出本轮小范围测试补强；不采用。

## 验收

- 草稿删除被拦截时，状态元素仍在打开的恢复弹窗内，带有约定的 live-region 语义；恢复删除能力后，已有重试路径仍移除快照。
- 外部删除草稿后，用户关闭恢复提示并触发 `pagehide`，存储键仍不存在。
- 完整 `npm test` 继续通过，且持久化、页面功能和 API 边界不发生源码变更。
